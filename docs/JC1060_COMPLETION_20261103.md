## Implemented behavior

- Memory bank: up to 16 ordered single cues/loops, full 32-byte media identity,
  separate `memorycue_v1` NVS namespace, version/CRC/size/owner checks. Empty
  local banks suppress source cues until explicit restore. Source files and
  Hot Cue banks are unchanged. STORE records the current CUE or active loop;
  DELETE removes that exact start. PREV/NEXT require a stopped, non-held deck,
  set its CUE and optional loop, and never autoplay. Recall/store respect known
  track bounds. Failed actions remain visible in the memory-panel title.
- Ordinary Hot Cues MEMORY panel exposes all five operations. HOLD SOURCE is
  intentionally distinct from the existing Hot Cue HOLD RESTORE. A memory
  gesture is bound to the pressed deck/media identity; source truncation is
  displayed and the list scrolls vertically. Network control exposes the same
  queued memory actions. DDJ-400's four store/delete inputs now compile to the
  new additive extended actions (v4, 288 inputs/127 outputs/6,176 bytes); existing
  FLX4 mappings and profile ABI are unchanged. New profile needs new firmware.
- Ordinary Settings persists LOAD LOCK, default ON. Failed NVS writes retain
  the published setting. Startup restores it after deck-core initialization.
- JC1060 Wi-Fi is optional/default OFF, WPA2 APSTA `Pajoniiir-JC1060`, with a
  separate switch from Ethernet DJ LINK. C6 transport is retained when stopping
  Wi-Fi; Ethernet HTTP remains available during OFF and AP/STA transitions.
  Ethernet readiness and saved enabled Wi-Fi remain required before confirming
  a pending OTA image. No Wi-Fi Link provider or default-ON Link was added.
- Touch clicks open selected folders/playlists, including the first selected
  row; clicking tracks only selects. Peer disappearance/reappearance or an epoch
  change reopens the root listing with fresh rows, preserving local navigation
  and loaded audio. Old downloads are invalidated, never resumed on a new epoch.
- SD power stays a separate build. Explicit `-SdColdPowerCandidate` packaging
  requires the enabled JC1060 configuration and board verifier, uses a separate
  directory and signed manifest field, and is rejected by the channel generator.
