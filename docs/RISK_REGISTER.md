# Risk Register

Status: current, reviewed 2026-07-13. Mitigated risks remain listed because a
future USB/audio/UI change can reintroduce them.

| Risk | Impact | Mitigation |
| --- | --- | --- |
| S3 USB host power or enumeration regresses | Blocks controller input | Enumeration and a 30-minute stability run passed on 2026-06-14; preserve raw logger diagnostics and recheck OTG port, powered hub orientation, 5 V VBUS, and shared ground after USB host changes |
| An extended Mixxx XML entry differs from actual hardware or from the official MIDI list | Wrong mapping for a non-MVP control or LED | MVP capture matched the XML exactly, so use XML addresses as implementation seeds; use the official Pioneer list as a secondary reference for LEDs/conflicts; hardware-smoke each delivered control group and record any exception in `DDJ_FLX4_MIDI_MAP.md` |
| Mixxx `Script-Binding` names are mistaken for standalone behavior | Incorrect state ownership or controls that behave differently from Mixxx | Use script-bound XML entries only for MIDI addresses; define semantic events explicitly and keep runtime deck/mixer/pad/effect state on the P4 |
| FLX4 controls or feedback generate noisy high-rate events | UART/USB MIDI queue pressure, jitter, or S3 task stack pressure | S3 translator coalesces high-rate jog/tempo/fader values; FLX4 VU feedback is treated as low-priority and dropped under MIDI OUT backlog; Phase 7 non-VU LED snapshot bursts are covered by a larger MIDI OUT queue, rate-limited full-queue warnings, and a 4096-byte `ctrl_rx` stack |
| Existing 7-byte control frame becomes too tight | Protocol churn | Use deck-aware ID namespace for MVP; only version frame if a real blocker appears |
| Dual MP3 decode exceeds CPU or memory budget | Audio dropouts/watchdog resets | P4 now has per-deck producer/mixer plumbing and shared output pacing; two-deck hardware smoke shows healthy PCM ring fill and memory margins; continue measuring before adding heavier DSP/UI work |
| Dual output summing clips with loud two-deck material | Audible distortion | Transparent post-sum limiter/soft-clip, telemetry, a persistent non-boosting Settings master trim, and a runtime FLX4 Master Level scalar are implemented; monitor limiter activity during hardware smoke tests and lower user-facing trim/level if sustained limiting is observed |
| MP3 preload/frame-index work briefly blocks audio/UI timing | Waveform or output timing spike | Active-output preload chunks are reduced, seek-table publishing uses a short lock, and audio late-warning diagnostics now report only >2x-period outliers instead of normal codec-write pacing |
| Dual output clocking or I2S routing is unstable | Cue/master output not usable | Master and cue/PFL routing are implemented for the current path; keep hardware smoke tests before adding heavier DSP |
| P4-to-S3 monitor PCM link regresses under product load | FLX4 USB headphones may click/drop if link integrity slips after integration changes | XIAO wiring is confirmed with raw I2S data, `P4HP` magic, block CRC over header+payload, and zero steady-state deltas for sequence gaps, CRC, I2S timeouts/errors, underruns, and overruns in the 2026-07-06 five-minute soak; the 2026-07-07 product e2e re-smoke confirmed audible FLX4 headphones with P4 TX `dropped=0`; the 2026-07-09 S3 rate-match fix removed product-path ring overruns by keeping the FLX4 USB Audio packetizer aligned with the active P4 link rate after stream start; rerun a numeric soak after any I2S, task-priority, or FLX4 USB Audio scheduling change |
| ES8311/speaker amplifier path is unsafe for headphone/line output | Hardware damage if the retired local speaker path is revived casually | Current product topology uses PCM5102A RCA MAIN OUT plus FLX4 USB headphones; keep the old ES8311/speaker amplifier path out of active UI unless the schematic is rechecked and bench-measured again |
| LED feedback mapping requires script behavior not present in XML controls | FLX4 LEDs may not respond as expected | MVP Play/Cue/PFL LEDs, extended pad/loop/sync/Beat FX LEDs, reconnect resync, and official-list LED rows are verified where recorded; use XML/Pioneer list addresses as seeds, keep LED state P4-owned, and hardware-smoke each new LED group |
| FLX4 briefly shows a one-time pad sweep around the initial two-deck load sequence | Cosmetic startup indication can look like Pad FX feedback although no effect or pad action is active | Classified low priority after 2026-07-13 dual-port capture: deck routing remained correct (`0x97` D1 / `0x99` D2), playback and pad modes were unaffected, and no stack/audio fault accompanied the indication. Initial inactive pad-bank OFF bursts are suppressed and load-time Hot Cue output is diffed; do not add broader LED timing workarounds unless the symptom becomes functional or reproducible as a specific remaining MIDI packet. |
| Live Overview waveform rendering regresses UI fluidity | Jitter or visible stalls while mixing | Keep expensive redraws behind `ui_overview_scheduler`; Deck 2 lower waveform uses the normal LVGL invalidation/flush path after the 2026-06-13 jitter fix; the current main waveform load path defers render/blit to the scheduler and reblits both deck overlays after track load so LVGL flushes do not blank another deck's direct overlay; use host scheduler tests plus COM15 smoke logs after renderer changes |
| Dense Overview chrome overlaps controls on the 800x480 P4 screen | Play/Cue, VU, title, or effect data becomes hard to read or touch | Keep compact fixed-size lanes for D1/D2 badges, VU meters, transport controls, title strip, and Beat FX rail; preserve static layout guards and do a hardware visual review after every Overview polish batch |
| Controller task performs heavy UI/library work | Stack overflow or UI-context bugs when hardware buttons navigate Library/Overview | 2026-06-25 smoke found a `deck` task stack protection fault on Browse; `deck` task stack is now 8192 bytes as a stabilizing fix. Future cleanup should marshal controller-triggered UI navigation onto the LVGL/UI task context instead of running table work on the deck-control task |
| P4 local build remains in debug optimization | Reduced UI/audio headroom and waveform jitter | `sdkconfig.defaults` now selects performance optimization and disables LVGL examples/demos. Regenerate or align ignored local `sdkconfig` files before flashing |
| Upstream code changes are mixed with DDJ-specific changes without notes | Hard to reason about port | Keep DDJ docs explicit and update development plan after each phase |
| Old experimental branches are merged accidentally | Reintroduces stale Smart/DSP or Wi-Fi-hosted code | Completed Codex branches were cleaned after the 2026-06-26 Phase 7 merge; the last experimental branch `codex/flx4-extended-controls` was reviewed and removed on 2026-07-03 after confirming its verified slices were already salvaged into `master`, so no non-master branches remain |
| OTA signing key is lost, copied or cannot be rotated | Unauthorized firmware could be signed, or legitimate future OTA releases could become impossible without wired access | Devices verify ECDSA P-256 bundles with committed key ID `rel-001`; an offline USB backup was confirmed during signed-path hardware acceptance on 2026-07-14. Keep both copies access-controlled and move production signing to encrypted or hardware-backed storage with a documented multi-key/rotation migration |
| Final enclosure changes power, temperature or RF behavior | Audio instability, brownout, USB disconnect or inaccessible service AP after USB ports become hard to reach | Run closed-enclosure dual-deck/audio soak, measure rail/temperature margins, verify AP reachability and retain a wired recovery/service path before sealing |
| Master Tempo quality or CPU cost degrades under simultaneous demanding material | Artifacts or deadline misses with key lock active on both decks | Basic hardware behavior is accepted; add long two-deck quality/CPU regression material before declaring production DSP quality |
| Only the FLX4 controller profile is end-to-end verified | Profile schema defects may remain hidden for other controller layouts | Validate one non-FLX4 controller including input, LED output, reconnect and profile fallback before advertising generic compatibility |
| A remote controller-profile overwrite is corrupt or loses power mid-write | The S3 could lose its active MIDI/LED mapping after the enclosure makes SD access difficult | P4 accepts only bounded CRC-valid S3CP v2 blobs, requires strict non-traversable IDs and explicit overwrite, serializes install against transfer, writes/syncs a same-directory staging file, preserves the previous target as a backup, recovers interrupted swaps during scan and reactivates only after a successful rescan; retain the built-in FLX4 fallback and hardware-test interruption before closing the feature |
