## Follow-up diagnostic change

The existing counters cannot distinguish an ISO SKIPPED status from ERROR
or a short completed packet. The next source adds `UAC_PACKET_FAULT` details:
status, actual bytes, requested bytes and gap since the previous successful
URB callback in RTOS ticks. Values are captured before descriptors are reused.
At most four detail records are enqueued per boot; no allocation, blocking,
filesystem access or successful-packet logging is added to the USB callback.
Existing event IDs are retained by appending the new event. Counters, latched
loss flags, format, pacing, queue depth and acceptance thresholds are unchanged.
The callback-gap history restarts with each successful stream prime.

This is diagnostic instrumentation, **not a fix or a qualified new image**.
Host tests exercise SKIPPED, ERROR, short-packet detail, healthy silence,
callback gap and the four-record cap while loss counters continue increasing.
Validation passed: targeted actual-stream tests, the full P4 host runner,
ESP-IDF 6.0.2 builds for both shared-core targets, unchanged dependency locks
and `git diff --check`. Preflight images are 2,566,064 bytes (JC4880) and
2,624,912 bytes (JC1060); both remain below `0x380000`. A clean pushed-source
build and signature check are still required before a diagnostic OTA.

Open: fault reproduction/cause/correction, controlled resource comparison,
remaining formats/transport/operator tests, reconnect/rollback matrix and final
exact-image >=180-minute soak. JC1060/DDJ-400/Link hardware remains NOT RUN.

## Heap-query timing investigation

Inspection of ESP-IDF 6.0.2 `heap_caps_get_largest_free_block` shows a TLSF
pool walk inside each heap's critical section. H introduced three such queries
in `audio_engine_snapshot_memory`, reached both by HTTP status and the 5-second
esp_timer health monitor. This is a scheduling risk, not yet a proven cause of
the skipped packets. A 200-request idle status burst added no packet failures;
a later idle observation had a new lifetime loss before the next PLAY.

The next diagnostic adds per-capability maximum query duration (including
preemption), and at most four `HEAP_WALK_SLOW` journal records per boot for
queries at least 500 us. Each records capability index 0/1/2, elapsed us,
start uptime ms and largest block. It neither measures IRQ-disabled duration
directly nor changes audio/USB admission, counters or acceptance thresholds.
Executable host coverage checks values, timing maxima and the bounded journal.

The diagnostic `b89c474c9753e84f035e8707a2c69e7b8283237e` passed full local
host tests, both firmware builds, unchanged locks and all eight jobs of CI
37270134618. A fresh clean JC4880 build with identical ordinary configuration
was signed/verified and installed as `M2.4-75-gb89c474c`, `ota_1`, boot 603.
Image size 2,566,512; SHA-256
`adc12bfa562a6ad4acede3787c94a3149cd7684f1593f2482a3ba1aeae77a3c2`;
bundle SHA-256
`8a91d913bc9c94d0631cd50873883403b7ef5545b65abc8957187a0320a6805f`.
AP/USB0/FLX4 returned. Idle query maxima were 90/61/560 us; after tracks
14/5 loaded paused they were 97/82/1,393 us. A dense HTTP status/dual-PLAY
run stopped on one new SKIPPED packet at approximately 66 seconds:
`boot=603 ms=165887 UAC_PACKET_FAULT a0=6 a1=0 a2=352 a3=3`.
Query wall-time maxima were 4,471/2,810/7,360 us including preemption, so these
are not measurements of uninterrupted critical-section time. Strict result FAIL.

An earlier H dense-status 183-second run also failed: two new packets and one
11,653-us output-late event. Its temporary monitor initially printed PASS
because PowerShell's `compare` alias shadowed the intended assertion function.
The raw before/end snapshots and journal supersede that output. The function
was renamed and a deliberately increased-counter self-test passed; the later
boot-603 run stopped correctly on its first increase. Other previously recorded
runs used a different monitor and are not reclassified by this script error.

Corrective experiment: remove the PSRAM largest-block walk from the shared
status/health snapshot in both idle and PLAY. UAC emits silence while decks
are stopped, so gating only on playback is insufficient. PSRAM free/minimum
and LVGL usage remain live; internal/DMA largest-block gates remain unchanged.
The optional JSON `psram_largest_free` becomes null, explicitly unavailable,
instead of presenting zero or cached data as a measurement. Host coverage
forbids any PSRAM largest-block query and verifies free/minimum values plus
clearing stale struct values. Hardware causality and regression remain open
until the new exact image repeats the same stress and longer observations.
